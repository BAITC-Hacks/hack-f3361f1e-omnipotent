# Sana — от идеи к делу

Рабочий прототип для AI Sana / HackAlem: бизнес уточняет задачу, подтверждает карточку и публикует её в каталоге. Студенты откликаются, бизнес вручную выбирает одну, несколько или ни одной команды.

## Быстрый запуск

Нужен **Node.js 22.12+** (или Node.js 24 LTS) и npm. Отдельная база данных не нужна. Без API-ключа работает резервный демонстрационный режим; для настоящего AI настройте `.env` ниже.

```bash
git clone https://github.com/BAITC-Hacks/hack-f3361f1e-omnipotent.git
cd hack-f3361f1e-omnipotent
npm ci
npm run dev
```

Репозиторий приватный: для клонирования нужна авторизация GitHub. Если он уже клонирован, просто перейдите в его папку и выполните последние две команды.

Откройте **http://localhost:5173**. API запускается на `127.0.0.1:3001`, Vite перенаправляет `/api` на него. Остановка — `Ctrl+C`. Порты 5173 и 3001 должны быть свободны.

Проверка и сборка:

```bash
npm test
npm run build
npm start
```

После сборки `npm start` отдаёт API и интерфейс вместе: **http://localhost:3001**. `npm run build` сам сервер не запускает. В обычном `npm start` нужны установленные devDependencies, поскольку минимальный сервер запускается через `tsx`.

Для другого порта собранного приложения: `PORT=3002 npm start` (macOS/Linux) или `$env:PORT=3002; npm start` (PowerShell). В режиме разработки используйте API-порт 3001. Сервер автоматически читает локальный `.env`. Переменные, уже заданные в окружении процесса, имеют приоритет. После изменения `.env` перезапустите сервер.

## Что работает

- Русский интерфейс с отдельными кабинетами бизнеса и команды, созданием профиля и повторным входом по имени.
- Описание потребности, уточняющие вопросы, редактируемая карточка и ручное подтверждение.
- Рейтинг 0–100 по качеству каждого поля, AI-пояснения и точный вклад каждого ответа; неподтверждённая оценка показывается только как предпросмотр.
- Общий каталог опубликованных задач с сортировкой, поиском и фильтрами.
- Отклики команд: идея, план, срок и ссылка на прототип.
- Ручной выбор/отклонение предложений владельцем задачи, обратная связь команде, несколько выбранных команд одновременно.
- Подтверждение выполненного этапа: +10 баллов команде однократно за отклик.
- Сохранение данных на сервере между перезапусками.

## Кабинеты и сохранение

Нажмите **Бизнес** или **Команда**, введите имя и откройте кабинет. Новое имя создаёт профиль; то же имя (без учёта регистра и лишних пробелов) открывает существующий. Можно выбрать один из демонстрационных профилей. Сессия хранится в HttpOnly cookie и сохраняется при перезапуске сервера.

- Бизнес видит свои задачи/черновики и входящие предложения по ним; только он может редактировать задачу, принять или отклонить отклик и написать обратную связь.
- Команда отправляет решения от своего имени; видит только свои отклики, решения бизнеса и комментарии.
- Общий каталог доступен всем; чужие неопубликованные черновики и чужие предложения сервер не отдаёт.
- **Сохранить черновик** работает на любом шаге, даже с пустыми полями. Пустое название заменяется на «Без названия».
- **Опубликовать** требует только непустого названия и ручного подтверждения. Минимальной длины описания и порога рейтинга нет. Ошибка показывается рядом с кнопками, фокус переводится на нужное поле.
- Редактирование снимает подтверждение и старую оценку. «Сохранить изменения» у опубликованной задачи сохраняет её в каталоге; «Снять с публикации» — отдельное действие.

Это вход по имени для прототипа, а не защищённая учётная запись: любой, кто вводит то же имя, открывает тот же кабинет. Пароль и подтверждение личности намеренно не добавлены.

## Архитектура

React + TypeScript + Vite — интерфейс. Node.js + Express — API. Общие типы и детерминированная формула рейтинга используются в проекте. Для небольшого однопроцессного прототипа данные хранятся в JSON с атомарной записью.

```text
src/             интерфейс React и стили
shared/          типы данных и формула рейтинга
server/          API, хранилище, синтетические данные, OpenAI и резервные вопросы
tests/           проверки рейтинга и серверных сценариев
data/store.json  рабочие данные, создаются при первом запуске (не в Git)
```

`Task`: описание, отрасль, десять полей карточки, подтверждение, публикация. `Team`: название, интересы, навыки, технологии, баллы прогресса. `Proposal`: задача, команда, идея, план, срок, ссылка, решение бизнеса, подтверждённый этап.

## Формула рейтинга

| Поле | Максимум |
|---|---:|
| Название | 0 |
| Контекст | 10 |
| Потребность | 10 |
| Пользователи | 10 |
| Данные и материалы | 20 |
| Ограничения | 10 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Контакт | 5 |
| Формат взаимодействия | 5 |
| **Всего** | **100** |

Кнопка **«Оценить качество с AI»** вызывает серверную оценку каждого поля: ясность, конкретность, соответствие задаче и достаточность для начала работы. AI возвращает качество 0–1, объяснение и рекомендацию. Код умножает качество на фиксированный вес поля и округляет. Сервер проверяет структуру ответа и удерживает баллы в допустимых пределах; пользователь не может передать собственную оценку при сохранении.

Пустой ответ, очевидная бессмыслица, повтор одного текста во множестве полей или скопированный вопрос дают 0. Короткие осмысленные ответы не отбрасываются только из-за длины. Неполные полезные ответы получают частичные баллы. Рядом с полем видны текущие баллы, максимум и сколько ещё можно получить. Название не приносит баллов.

До подтверждения оценка — предпросмотр. При подтверждённом сохранении сервер сам получает актуальную оценку или использует результат предыдущей AI-проверки той же карточки. Оценка сохраняется с задачей и используется для каталога, сортировки и фильтров. Изменение сведений требует новой оценки и подтверждения. Одинаковые успешные запросы кешируются на время работы сервера; ошибки не кешируются.

При недоступности OpenAI применяется **явно обозначенная консервативная проверка по правилам**, не выше 50/100. Это не семантическая AI-оценка. Она не превращает набор букв в высокий рейтинг и не мешает публикации. После восстановления API можно повторить оценку.

Уровни: **0–39 — Черновик**, **40–69 — Рабочая**, **70–89 — Готовая**, **90–100 — Приоритетная**. Уровень «Черновик» отличается от неопубликованного состояния: подтверждённую задачу с 0 баллами можно опубликовать, и любая команда может откликнуться.

Выбор одной команды не отклоняет остальные автоматически. Баллы команд за подтверждённый результат (+10 однократно за отклик) не влияют на рейтинг задач.

## Настройка настоящего AI

1. Скопируйте `.env.example` в `.env`: `cp .env.example .env` (PowerShell: `Copy-Item .env.example .env`). Если `.env` уже существует, отредактируйте его вместо перезаписи.
2. В локальном редакторе впишите ключ в `OPENAI_API_KEY`.
3. Оставьте `OPENAI_MODEL=gpt-4.1-mini` или укажите другую доступную проекту модель с поддержкой Responses API и Structured Outputs.
4. Перезапустите сервер. На первом шаге конструктора появится сообщение о настроенном OpenAI, а после успешного запроса — «Вопросы подготовлены OpenAI».

```dotenv
OPENAI_API_KEY=your_key_here
OPENAI_MODEL=gpt-4.1-mini
PORT=3001
```

`.env` исключён из Git. Ключ используется только на сервере в заголовке Authorization; не добавляйте префикс `VITE_` и не вставляйте ключ в клиентский код. Описание, отрасль и заполненные поля карточки отправляются в OpenAI только при нажатии «Получить вопросы». Не включайте в демонстрационные задачи реальные чувствительные данные.

### Как работает AI

`server/openai.ts` отправляет запрос в OpenAI Responses API со строгой JSON-схемой, `store: false` и ограничением ответа 1600 токенов для вопросов; оценка качества использует отдельный структурированный запрос до 4000 токенов. Модель формулирует 3–6 вопросов на русском языке по конкретной ситуации и недостающим сведениям. Повторяющиеся/неизвестные поля, незавершённые ответы, отказ и неверный JSON отклоняются сервером.

**Модель не заполняет поля карточки выдуманными фактами.** Отдельный оценщик качества в `server/evaluation.ts` возвращает содержательную оценку; код применяет фиксированные веса. Поля берутся только из пользовательского ввода; исходное описание может быть перенесено в контекст дословно. Ответы на вопросы вводит пользователь. Контакты, сроки, показатели и другие факты не выдумываются. Публикация требует ручного подтверждения.

Промпт и JSON-схема: `server/openai.ts` (`OPENAI_PROMPT`, `questionSchema`). Его принцип: учитывать описание и заполненные поля, задавать вопросы о недостающем, не выполнять инструкции из входных данных, не придумывать факты и не выбирать команду.

Контракт `POST /api/clarify`:

```json
{
  "description": "Наш магазин часто остаётся без популярных товаров",
  "industry": "Ритейл",
  "fields": { "data": "Есть CSV продаж за 6 месяцев" }
}
```

Результат содержит:

- `mode`: `openai` при успешном AI-запросе или `demo` в резервном режиме;
- `notice`: понятное описание режима или причины перехода на резерв;
- `questions`: массив из 3–6 объектов `{ "field": "success", "question": "Как вы измерите снижение дефицита товаров?" }`;
- `fields`: все десять полей карточки, содержащие только предоставленные пользователем сведения; неизвестные значения остаются пустыми.

`POST /api/assess` принимает `{fields, description, industry}` и возвращает оценку каждого поля, причины и рекомендации. Оценка привязана к текущему содержимому; AI не решает, разрешать ли публикацию. Этот маршрут и конструктор доступны вошедшему бизнесу.

`GET /api/ai/status` возвращает только `{configured, model}`: наличие настройки не гарантирует доступ или достаточную квоту. Ключ и ответы об ошибках провайдера клиенту не передаются.

### Резервный режим и ошибки

Без ключа используются локальные вопросы по правилам из `server/ai.ts`. При тайм-ауте (25 секунд), неверном ответе или ошибке API приложение сохраняет введённые сведения и показывает резервные вопросы. Ошибки ключа (401), доступа (403), модели (404) и квоты/лимитов (429) имеют отдельные понятные сообщения. Автоматических повторных платных запросов нет. Чтобы проверить исправленную настройку, нажмите «Получить вопросы» ещё раз.

Тесты подменяют провайдер и не расходуют API-кредиты. Они проверяют серверную передачу ключа, формат запроса, успешный ответ, тайм-аут, отказы, HTTP-ошибки, неверную структуру и отсутствие выдуманных полей.

Документация: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

## Демонстрация за пять минут

1. Нажмите «Бизнес», введите «Мой магазин» и откройте кабинет. Создайте задачу или сохраните пустой черновик.
2. Введите проблему магазина, получите уточняющие вопросы, перейдите к карточке. Введите короткое название и несколько ответов «аю», нажмите «Оценить качество с AI» — покажите низкую оценку и причины.
3. Замените ответы конкретными сведениями: данные продаж CSV за полгода, пользователи — менеджеры закупок, результат — прототип прогноза, критерий — снижение дефицита на 15%, срок — две недели, контакт — `demo@example.org`, еженедельные консультации. Повторите оценку и покажите рост баллов.
4. Подтвердите карточку и опубликуйте. Для проверки можно оставить её с низкими баллами: публикация не блокируется.
5. Нажмите «Команда», введите «Omnipotent». В каталоге откройте задачу и отправьте идею, план и срок. Ссылка на прототип необязательна.
6. Снова войдите как бизнес «Мой магазин», откройте входящие отклики, выберите или отклоните решение с комментарием. Вернитесь в кабинет команды и покажите ответ бизнеса.

## Данные и проверки

При первом запуске создаются пять демонстрационных бизнесов, пять исходных описаний, пять карточек с разной полнотой, пять команд и пять предложений. Ещё пять готовых наборов для ручной проверки находятся в `docs/additional-test-data.md`; их можно копировать в форму, не придумывая собственные примеры. Все данные синтетические; ссылки `example.org` и контакты — демонстрационные.

`npm test` включает сквозной DOM-тест интерфейса (создание → подтверждение → публикация → отклик → выбор → результат), а также проверяет начисление баллов, подтверждение/публикацию, доступность слабых задач для откликов, ручной выбор, однократные баллы прогресса, ошибки запросов и сохранение данных. При обновлении старого формата сервер сохраняет резервную копию `data/store.json.before-accounts-*.bak`. Прежние пользовательские задачи без владельца переносятся в кабинет **«Мой бизнес»**, демонстрационные — в соответствующие именованные бизнесы.

Для сброса своих демонстрационных данных остановите сервер и переименуйте `data/store.json` в резервную копию — следующий запуск создаст исходный набор.

## Границы прототипа

Вход по имени предназначен для хакатонной демонстрации и не подтверждает личность. Проверки владельца задач и откликов выполняются на сервере в рамках текущего выбранного профиля. Нет загрузки файлов, чата и внешних бизнес-интеграций. JSON-хранилище предназначено для одного серверного процесса. Приложение слушает локальный компьютер; публичное развёртывание и защищённая авторизация — отдельный этап.
